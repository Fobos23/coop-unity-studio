## Pending (ask the director at the end of a phase or session) (7)
- **L001** [process] A project with its own process keeps it: an existing game whose CLAUDE.md and project skills define its process and that has no studio docs/ROADMAP.md: follow the project's process and skills (build, tests, maps); use the studio's references only as a reference, never bootstrap or init.sh unless the director asks to adopt the studio — when: the studio triggers inside a game made before it, e.g. Zombolic (ship skill, autotest.sh, its own roadmap)
- **L002** [fix, phase 3] Editor steps must not create temp objects in the active scene: Editor steps make their temporary GameObjects (prefab building, generated roots) in a throwaway additive scene or set the target scene active first; Builder.BuildPlayer refuses when an open scene is dirty instead of building. — when: any idempotent editor step or build run by eval in a shared editor
- **L003** [fix, phase 3] NGO prefabs saved by script keep GlobalObjectIdHash 0 on disk: After PrefabUtility.SaveAsPrefabAsset of a NetworkObject prefab, AssetDatabase.ForceReserializeAssets(path) and read the hash back from the file; fail the step if it is 0. — when: editor steps that build network prefabs
- **L004** [process, phase 2] Generated concepts only after the board, with the liked references attached: In phase 2 show the board of real references first. Order generated concept sheets only after the director has marked likes and not-its, attach the liked frames to the generator and list the not-its in the brief. Curate Steam screenshots by eye before the board: the first ones are often menus and aerial views. — when: Any style or character choice where an image generator is available.
- **L005** [technique, phase 5] Measure the pace of emergent crowd events with a headless shift sim before tuning: Before changing the numbers of an emergent rule (brawls, panics, queues), run the crowd simulation without a scene for a whole session with the real door/waves and a simple model of players (supply every N s, reaction to events) and print events per session, peak and mean at once, share of time, damage. Compare variants side by side; then freeze the chosen numbers into a logic test (events per session in a band). — when: a playtest says an emergent event happens too often or too rarely
- **L006** [fix, phase 5] Editor physics labs must clear the dirty flag of DynamicsManager: An editor tool that sets Physics.simulationMode = Script for Physics.Simulate marks ProjectSettings/DynamicsManager.asset dirty even when it restores the mode; the next save (a player build) rewrites the file in the new serialized format. In the tool's finally: restore the mode and EditorUtility.ClearDirty every object of AssetDatabase.LoadAllAssetsAtPath(ProjectSettings/DynamicsManager.asset). — when: writing an editor-side physics test bench (ragdolls, throws) that steps physics by hand
- **L007** [process, phase 2] Model orders: measured budgets, a compare sheet and an independent re-import: When ordering models from a generator agent (Codex with headless Blender): take triangle budgets from a measurement of what the game draws now, not from a guess; give stylised props their exaggerated sizes in the brief; require a side-by-side sheet with the approved concept and PASS or FAIL against each limit; then re-import every FBX yourself with a small Blender script before believing the report. — when: Any batch of generated 3D models before it goes to Unity.

## Applied (6)
- **L008** [process, phase 6] In a game with a settled look, ask the director for their own references before direction cards: When a new place or feature is designed inside a game whose look is already set, first ask the director for 2-3 pictures of what they imagine; build direction cards only if they have none, and then from the game's own style (its packs and build shots) rather than from photos of real places and other media. — when: phase 5-6 content cards: a hub, a base, a new map area; not phase 2 of a new game → references/style.md
- **L009** [fix] Baked binary .asset files must be marked binary in .gitattributes: The common Unity .gitattributes template sets '*.asset ... eol=lf' without 'text'; git then converts line endings without looking at the content, so a CR LF pair inside a baked binary NavMesh drops a byte and Unity refuses to load the file ('Unknown error occurred while loading'). Mark baked binary assets binary ('*NavMesh.asset binary', 'NavMesh-*.asset binary', 'LightingData.asset binary') and add a pre-commit check: a staged .asset whose blob has a NUL byte in its first 8000 bytes while git check-attr says text=set, or text unspecified with eol set, blocks the commit. A Unity binary serialized file declares its size in the header (offset 24, 8 bytes big-endian for format >= 22): compare it with the blob size to find already-damaged files. — when: phase 0 (template .gitattributes) and whenever a build log shows 'Unknown error occurred while loading' for a baked asset → templates/Tools/dev/githooks/pre-commit.sh, scripts/init.sh, references/unity-windows.md
- **L010** [process, phase 7] A boring or empty map is a space problem first: When a playtest calls a map empty, easy or 'did the task and left', measure the space - size, street widths, sightlines against the AI sight range, relief, routes, respite - before proposing a mechanic, an AI rule or a balance change. — when: after a playtest or a director's remark that a map is boring; before writing any design fix for it → references/design.md, references/level-design.md, SKILL.md
- **L011** [technique, phase 6] Level design rules come from the game's own numbers: Derive map limits from balance data: sightlines from the AI sight range, map size and respite spacing from sprint speeds, relief steps from jump height, safe fall and the kit's storey; three street widths, three routes overlapping at most a third, respite buildings with two real exits; every story place read in three layers and given a passport before dressing; one legend per map. — when: phase 6, designing any new map or reworking one → references/level-design.md, templates/docs/MAP_PASSPORT.md, references/maps.md, references/phases.md
- **L012** [technique, phase 6] What breaks a sightline: tall staggered blockers, offsets with a building, walls at the street: Cars do not block sight (the eye is above the roof) - buses, lorries, tents, blind fences and houses do; one blocker across a street is not enough, two staggered ones are; a street offset needs its width plus a building; walls stand right at the street; the vehicle's street is broken only by a bend. — when: laying out streets and blockers on a map scheme or a gray build → references/level-design.md
- **L013** [tool, phase 6] Map scheme from one coordinate table, checked by script before anything is built: Draw a new map as one JSON table (levels, ramps, streets, buildings at real footprints and doors, tall and low blockers, routes, spawns) and run scripts/map-scheme.py: two to-scale sheets plus checks of route length and overlap, distance to a respite door and the longest sightline. Iterate the layout against the checks; the director approves the sheets before a gray build. — when: phase 6, step 'scheme' of the map cycle; also to show a director a layout without opening Unity → scripts/map-scheme.py, templates/docs/map-scheme.example.json, references/level-design.md
